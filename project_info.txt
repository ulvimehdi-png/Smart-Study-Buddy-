Project: Study Management Dashboard
=======================================

1. Project Explanation:
-----------------------
This is a modern web application designed for students to track their study progress.
- Backend (Symfony): Handles the business logic, database interactions, and API endpoints.
- Frontend (React): Provides a sleek, interactive user interface for managing notes, tasks, and sessions.
- Database (MySQL): Stores user data, sessions, tasks, and achievements.
- Real-time (Mercure): Allows the app to push live updates (like study timer sync) to the frontend.

Key Features:
- Dashboard: Overview of total study hours, notes, and task progress.
- Notes: CRUD operations for study notes with subject categories.
- Tasks: To-do list with status tracking (Todo, In Progress, Done).
- Study Sessions: Timer-based sessions that track actual focus time.
- Gamification: Point system and achievements to motivate studying.

2. Why "localhost:8000/api" is not opening:
-------------------------------------------
The URL "localhost:8000/api" by itself is NOT a valid page in this project.
- The project is not using "API Platform" (which usually provides a documentation page at /api).
- Instead, it uses custom controllers where "/api" is just a prefix for specific functional endpoints.
- To verify the API is working, try visiting: http://localhost:8000/api/user (it should return a JSON response).

3. Why the database is not working:
-----------------------------------
There are three common reasons why your database might appear to be "not working":

A. Port Mapping Conflict:
   - In your Docker configuration, MySQL is mapped to port 3307 on your host machine (to avoid conflicts with local MySQL).
   - If you are running Symfony LOCALLY (outside Docker), your .env should use:
     DATABASE_URL="mysql://app:app@127.0.0.1:3307/app"
   - If you are running everything via DOCKER, your .env.dev should use:
     DATABASE_URL="mysql://app:app@database:3306/app"

B. Missing Tables (Migrations):
   - Even if the connection is successful, the database might be empty.
   - You need to run the migrations to create the tables.
   - Command (if running locally): php bin/console doctrine:migrations:migrate
   - Command (if using Docker): docker exec -it <php_container_id> php bin/console doctrine:migrations:migrate

C. Container Status:
   - Ensure the database container is actually running. Run "docker ps" to check.
   - If "docker-database-1" is not listed, run "docker compose up -d" from the docker directory.
